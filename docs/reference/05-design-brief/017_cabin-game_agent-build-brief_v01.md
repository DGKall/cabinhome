目标是在山脚前的开阔草甸上建立一座可逐步升级的小屋场景，兼顾休闲、治愈、静谧与植物鲜活感，并控制后续建模和内容生产成本。

| 状态 | 内容 | 执行方式 |

| 用户已确认 | 以 009 梦核简化画风为主；喜欢阿勒泰花甸、梦核草坡；靠近山脚；扩大升级空间 | 必须保持 |
| 用户已确认 | 图示需要表达面积、地形及升级空间；素材存入桌面 draft 并规范命名 | 必须保持 |

| 工作基线，未获最终数值确认 | 160×120 m 活动范围、64×48 m 升级台地、48/120/192 m² 主屋分期及全部地形参数 | 可据此制作可逆灰盒；不可写成已获用户最终批准 |
| 尚未决定 | 游戏引擎、设备与性能目标、最终相机控制、室内玩法深度、角色尺度、最终资产预算 | 制作引擎中立资产；依赖这些选择的专项工作先留后续 |

## 2 美术方向

主参考：PDF 第 1 页（009）；环境与色调参考：PDF 第 2 页（004、006）。

- 形体：自然比例的小屋、舒展的草坡、概括的山体、少量成组树木；可以简化细节，不把房屋变成夸张玩具比例。
- 色彩：鼠尾草绿草地、蓝绿远景、灰紫阴影、浅暖木色、奶白积雪；黄昏点缀低饱和粉色，蓝调保留可读的地面。
- 材质：以哑光大色块和少量手绘变化为主；木纹、草叶和山石微细节要克制。
- 植被：小花、草簇在边缘和小径附近成组；中间保留明显开阔地。重复实例结合疏密、尺度和少量色差，不铺满整地。
- 环境关系：近山在北面形成包围；前方草地与南/东南方向湖景、远雪山拉开距离。
- 009 是氛围与形体参考，不是三视建模图。四格中的门窗、屋顶可能不完全一致，应建立一套一致模型，再从不同角度验证。
- 不沿用 001 的厚重油画笔触、整面金黄光照和均匀繁密植物；不回到写实级木纹、密集草叶与复杂反射。

本轮不锁定精确色值、曝光、雾密度或灯光强度；先让几何、构图和大色块成立，再进行微调。

## 4 坐标与地形的唯一工作基线

- 规划坐标 P：单位米；西南角为 XY 原点；X 向东，Y 向北，Z 向上。下方 bounds 顺序统一为 `[xmin, ymin, xmax, ymax]`。
- 规划 Z 是相对标高。推荐 Blender 场景坐标 B 使用 `B=(P.x,P.y,P.z-99)`，使南缘地面接近 Z=0；禁止只移动房屋而漏移地形、相机或附件。
- 因此主屋完成地坪在规划 Z=101、Blender Z=2。主屋南北两端地面约为规划 Z=100.39/100.54，基础外露高差约 0.61/0.46 m。
- 山体为北侧背景边界；场外湖面与远雪山只先做低成本背景，不扩张可玩区域。
- 默认可建坡度 5% 是待验证建议，不是已实现的游戏规则。
- 地形公式使用米与弧度。4 m CSV 是公式采样结果；需要更密网格时直接重新采样公式。不要把粗网格插值误差当成新设计。

同一地形的可直接移植伪代码：

```python
from math import sin

def height_plan_m(x, y):
    if y < 38:
        return 99 + 0.03 * y
    if y <= 86:
        return 100.14 + 0.0125 * (y - 38)
    t = y - 86
    return 100.74 + 0.32 * t + (0.018 + 0.004 * sin(x / 25)) * t * t

def height_blender_m(x, y):
    return height_plan_m(x, y) - 99
```

原公式的 Y=38/86 处分段斜率并不连续；第一版按公式验证空间。后续若做平滑，应守住台地尺寸、地坪和后场距离，并记录修改后的公式与版本。

## 5 建模与导出约定

以下是为了便于 agent 开始工作提出的首轮约定，可在用户选择引擎后更新。

1. 首选 Blender 原生 `.blend` 工作文件，并提供引擎中立 `.glb`。这是建议交付约定，不代表当前已经制作这些模型。
2. 一个 Blender 单位 = 1 m；场景采用上述 B 坐标。glTF 轴向转换交给导出器处理，导入后核对尺寸与朝向，不重复手动交换轴。
3. 主屋壳体局部原点位于西南外墙角的完成地坪，局部 (0,0,0)；阶段 1 放置到场景 (72,58,2)。基础作为独立对象，向下贴合地形。
4. 房屋占地以外墙包络计；屋檐外挑另记录，不混入 48/120/192 m²。门窗尺寸、墙厚、屋檐外挑和室内布局尚未确认。
5. 参考剖面暂用檐口高 3.2 m、屋脊高 5.0 m（均相对完成地坪），屋脊东西向。不同阶段进深变化会改变坡度；先做各阶段独立屋顶体块，不假定一个屋顶模块能不变形覆盖全部阶段。
6. 建筑先采用 2 m 水平模数作为候选；地板、实墙、门墙、窗墙、屋顶和基础拆分。模数为生产建议，不改变整体外包尺寸。相邻模块不得叠出重复外露墙或闪烁面。
7. 普通可摆放道具原点在底部中心；墙板模块原点在左下拼接角；门可单独拆出并以铰链为旋转原点。各对象的规则需记录在模型交付说明中。
8. 使用少量共享材质：浅木、深木/边框、灰蓝屋顶、草地、石头、雪、花草、窗光。先保证基础色和粗糙度可用；不依赖某引擎专属着色器。
9. 草花用少量可复用网格簇；树木用概括树冠；避免一片草地合并成无法调整的巨型静态网格。碰撞体只先给地面、房屋与重要障碍，花草不逐株添加。
10. 第一轮不制作角色、完整家具库、天气系统、种植系统、建筑经济或全部远期房间。留出接口即可。

原型级面数参考（可调整，不是已验证性能预算）：单栋阶段 1 外壳优先控制在 15k 三角面内；单棵树 0.5k-2k；草花簇 30-300；石块 100-500。实例数量、材质数量、阴影和过度绘制同样影响成本，禁止仅以面数承诺帧率。先用共享材质；确需贴图时以 1k 图集为起点，目标平台未定前不批量制作 4k 贴图。

## 7 工作顺序与阶段交付

### 阶段 A 空间灰盒

读取本说明和 PDF 1-5 页；建立米制场景、地形、阶段 1 小屋、阶段 2/3 包络、主入口与功能区预留。核对实际包围盒与坐标，不从图片中估尺寸。输出 `.blend`、可导入 `.glb`、一张带标注俯视图和一张南北剖面。

阶段 A 之后保持模型可编辑，提交灰盒供 review。用户尚未确认尺寸时，不把它们升级成不可更改的最终规格，也不提前批量精模。

### 阶段 B 风格验证

在灰盒上加入共享材质和极少量草花树石，只验证局部场景。用同一模型渲染黄昏远景、蓝调建造视角、雨天近景、窗内远景。雨天可以先用灯光与简单湿润色块表达，不要求完整天气模拟。

### 阶段 C 模块与扩展

待布局与风格接受后，再完善模块接缝、门窗、扩建方式、植被变体与 LOD。工坊、温室等进入各自任务，不默认扩大本轮范围。
